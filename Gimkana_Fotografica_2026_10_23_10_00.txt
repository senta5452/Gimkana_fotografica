## 3. Objectiu final de l'aplicació

Vull publicar una aplicació web amb una URL pública perquè diversos dispositius puguin participar en una mateixa partida.

Hi haurà tres accessos:

1. **Jutge:** inicia sessió amb correu electrònic i contrasenya, crea partides i revisa les fotografies.
2. **Equip A:** introdueix el codi de partida i el PIN de l'equip A.
3. **Equip B:** introdueix el codi de partida i el PIN de l'equip B.

Cada partida tindrà el seu propi codi, dos PINs, dos equips i els seus reptes.

Funcionalitats desitjades:
- Temporitzador de 20 minuts.
- Afegir 3 minuts per cada repte aprovat.
- Pausar i reprendre el temporitzador.
- Enviar fotografies per completar reptes.
- El jutge aprova o rebutja fotografies i pot afegir comentaris.
- Historial d'enviaments.
- Condicions de finalització de la partida.
- Reinici de partides.
- Estat compartit entre dispositius.
- Actualitzacions en temps real.
- Fotografies guardades permanentment.
- Publicació final amb una URL pública.

**Important:** tot l'estat de la partida (rellotge, estat, final, resultat, enviaments i reinici) ja surt del servidor i el codi local antic s'ha retirat (Fase 5, passos 5-7), però l'aplicació encara no està publicada ni s'ha provat amb dispositius diferents de debò, i les partides noves no tenen reptes (Fase 2). No afirmar que està acabada ni publicada.

### 4.8. Taules de Supabase i columnes

Les cinc taules existeixen: `games`, `teams`, `challenges`, `submissions`, `team_sessions`.

`games`: `id` uuid, `judge_id` uuid (FK a auth.users, cascade), `name` text, `status` text (default `setup`; només admet `setup`, `active`, `paused`, `finished`), `duration_seconds` int (default 1200, > 0), `started_at`, `finished_at`, `created_at`, `game_code` text (únic, en majúscules), `clock_started_at` timestamptz i `elapsed_seconds` double precision (default 0).

`teams`: `id` uuid, `game_id` uuid (FK, cascade), `team_key` text (només `A` o `B`, únic per partida), `name`, `access_code_hash`, `created_at`, `finished_at` timestamptz, `finish_reason` text (només `completed` o `timeout`), `finish_elapsed_seconds` double precision.

`challenges`: `id` uuid, `team_id` uuid, `title` text, `description` text (nullable), `position` int4, `approved` bool, `created_at`.

`submissions`: `id` uuid, `challenge_id` uuid (FK a challenges, cascade), `submitted_by_team` uuid (FK a teams, cascade), `photo_path` text (obligatori), `status` text (default `pending`; `pending`, `approved` o `rejected`), `judge_comment` text, `received_at` timestamptz (default now()), `reviewed_at` timestamptz.

`team_sessions`: guarda `token_hash`, `team_id`, `expires_at`, `revoked_at` (hi ha més columnes que no hem revisat).

## 5. Edge Functions

Les funcions utilitzen variables de servidor com `SUPABASE_URL`, `SUPABASE_SECRET_KEYS` i, les del jutge, `SUPABASE_PUBLISHABLE_KEYS`. No demanar-me les claus ni posar-les a `App.tsx`. Cada carpeta de funció té `index.ts`, `deno.json` i `.npmrc` (les noves es creen copiant els dos últims de `judge-set-game-state`).

**Funcions d'equip i públiques (sessió d'equip amb token propi):**
- `create-game`: crea la partida i els equips A i B, amb el codi i els PINs (JWT del jutge).
- `join-game`: valida codi, equip i PIN i crea una sessió d'equip (té `verify_jwt = false` a `config.toml`). Admet partides `finished`.
- `validate-team-session`: valida el token personalitzat de sessió de l'equip.
- `get-team-game`: dades de la partida, l'equip, els reptes, els enviaments (amb `photoUrl` si la partida ha acabat), el rellotge (`clock`, `serverNow`) i el resultat (`result`).
- `submit-photo`: pujada d'una foto d'un equip (4.11); rebutja si la partida no és `active` o l'equip ha acabat.

**Funcions del jutge (JWT de Supabase Auth, validat amb `auth.getUser`, i comprovant que la partida és del jutge per `judge_id`):**
- `judge-list-submissions`: equips (amb `clock`), reptes, `game` (estat i `serverNow`) i enviaments amb enllaços temporals a les fotos.
- `review-submission`: aprova o rebutja un enviament. No es pot aprovar si la partida ja és `finished` ni si l'equip ja ha acabat (per temps esgotat o per llista completada), ni un repte ja aprovat; en aprovar l'últim repte pendent d'un equip es desa `teams.finished_at`, `finish_reason = 'completed'` i `finish_elapsed_seconds`, i la partida passa a `finished` (`finished_at`, `elapsed_seconds` actualitzat, `clock_started_at` buit). Si falla algun pas, es desfà l'aprovació.
- `judge-set-game-state`: inicia, pausa i reprèn la partida.
- `judge-reset-game` (publicada i confirmada): rep `gameId`. Torna la partida a `setup` (`started_at`, `finished_at`, `clock_started_at` buits, `elapsed_seconds = 0`; manté `duration_seconds`), esborra els enviaments dels dos equips, desmarca tots els reptes, buida els camps de final dels equips i esborra les fotos de la partida del bucket (carpetes `<game_id>/<team_id>/`, també les fotos òrfenes de proves antigues). Primer posa la partida a `setup`, perquè no entrin fotos noves mentre es reinicia. Si falla l'esborrat de fotos, la partida queda reiniciada igualment i només es registra l'error. Les sessions dels equips no es tanquen. Retorna `removedPhotos`.

Patró d'autenticació dels equips: token personalitzat → hash SHA-256 → fila a `team_sessions` no revocada ni caducada → equip → partida. Patró del jutge: capçalera `Authorization: Bearer <token>` → `auth.getUser` amb la clau publishable → client amb clau secreta (`admin`) → comprovar `judge_id`. Les respostes d'error van en català i usen els mateixos CORS que la resta.

El fitxer `supabase/config.toml` només inclou:


## 11. Consulta SQL de reinici manual (SQL Editor de Supabase)

Normalment n'hi ha prou amb el botó Reiniciar del jutge. Aquesta consulta serveix per canviar la durada d'una partida de prova (el botó la manté). Canviar només les dues primeres variables. Esborra els enviaments d'aquella partida (els fitxers del bucket es queden). Si el codi no existeix, dona l'error "No hi ha cap partida amb el codi …". No seleccionar text abans de prémer Run (si no, només s'executa la part seleccionada).

```sql
do $$
declare
  v_code text := 'CODI';      -- codi de la partida de prova
  v_duration int := 60;       -- durada en segons (1200 = 20 min)
  v_game uuid;
begin
  select id into v_game from games where game_code = upper(v_code);

  if v_game is null then
    raise exception 'No hi ha cap partida amb el codi %', v_code;
  end if;

  delete from submissions
  where submitted_by_team in (select id from teams where game_id = v_game);

  update challenges
  set approved = false
  where team_id in (select id from teams where game_id = v_game);

  update teams
  set finished_at = null,
      finish_reason = null,
      finish_elapsed_seconds = null
  where game_id = v_game;

  update games
  set status = 'setup',
      started_at = null,
      finished_at = null,
      clock_started_at = null,
      elapsed_seconds = 0,
      duration_seconds = v_duration
  where id = v_game;
end $$;
```
